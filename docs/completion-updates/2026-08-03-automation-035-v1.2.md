## Defect found

The repository v1.1 helper attempted to normalize values greater than `3` by dividing by `100`. Airtable percent fields already return ratio values, so the Schmidt test value `83.7` represents `8,370%`. The old heuristic converted it to `0.837` and incorrectly returned `skipped_goal_below_100` even though `Threshold XP Ready? = 1`.

## v1.2 correction

`goalMeetsPercent` now compares the Airtable ratio directly:

```js
return ratio + 1e-9 >= percent / 100;
```

Examples:

- `1` = 100%
- `1.25` = 125%
- `1.5` = 150%
- `83.7` = 8,370%
