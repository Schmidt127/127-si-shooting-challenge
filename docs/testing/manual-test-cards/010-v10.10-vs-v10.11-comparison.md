## Summary

**v10.11 is a single behavioral change:** how date-only values are converted to calendar date keys inside `dateKeyFromDateObject`. All reconciliation, Source Key, ownership, acknowledgement, and fail-closed rules are unchanged from v10.10.

## Exact code difference

**File:** `airtable/automations/shooting-challenge/010-submission-intake-create-xp-event.js`

**Location:** helper `dateKeyFromDateObject` (shared with Activity Date / week boundary checks)

**v10.10 behavior:** Every `Date` object is formatted with `Intl.DateTimeFormat` in `America/Denver`, which can shift **midnight UTC** date-only values to the **previous Denver calendar day**.

**v10.11 addition:** Before Denver formatting, if the timestamp is exactly `YYYY-MM-DDT00:00:00.000Z`, return the UTC calendar components as `YYYY-MM-DD` without timezone shift.

```javascript
// v10.11 only — inserted at start of dateKeyFromDateObject
if (
  dateValue.getUTCHours() === 0 &&
  dateValue.getUTCMinutes() === 0 &&
  dateValue.getUTCSeconds() === 0 &&
  dateValue.getUTCMilliseconds() === 0
) {
  const year = dateValue.getUTCFullYear();
  const month = String(dateValue.getUTCMonth() + 1).padStart(2, "0");
  const day = String(dateValue.getUTCDate()).padStart(2, "0");
  return `${year}-${month}-${day}`;
}
```

**Metadata-only diff:** `SCRIPT.version`, `versionDate`, `Last Updated`, GitHub header date → v10.11 / 2026-08-20.

**No diff in:** Source Key contract (`SUBMISSION_XP|{Submission ID}`), XP Event create/update paths, reconciliation acknowledgement, milestone downstream flag, outputs, CONFIG tables, or trigger contract.
