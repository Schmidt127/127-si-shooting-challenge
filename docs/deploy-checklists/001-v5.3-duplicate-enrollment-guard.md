# Automation 001 v5.3 — duplicate Enrollment guard

**Status:** GitHub implementation ready; DEV validation and Production promotion pending
**Date:** 2026-08-11
**Automation:** 001 — Enrollment Intake and Setup — Find or Create Athlete and Link Enrollment
**Canonical script:** `airtable/automations/shooting-challenge/001-enrollment-intake-and-setup-find-or-create-athlete-and-link-enrollment.js`

## Defect

A repeat registration reused the existing Athlete but left a second active Enrollment for the same Athlete and School Year. Both rows then computed the same `Enrollment Key`.

## v5.3 behavior

- Set the incoming Enrollment inactive while identity and uniqueness checks run.
- Reuse or create the Athlete using the existing v5.2 identity rules.
- Link the incoming Enrollment temporarily, then check all Enrollments for the same Athlete and School Year.
- When no match exists, activate the incoming Enrollment and finish with `Athlete Match Status = Linked`.
- When a prior match exists, preserve the prior Enrollment as canonical and leave the repeat row:
  - `Active? = false`
  - `Athlete` blank
  - `Athlete Match Status = Error`
  - output `actionTaken = duplicate-enrollment-blocked`
  - output `duplicateOfEnrollmentId = <canonical record id>`
- A returning Athlete in a different School Year remains allowed.

No schema change is required.
