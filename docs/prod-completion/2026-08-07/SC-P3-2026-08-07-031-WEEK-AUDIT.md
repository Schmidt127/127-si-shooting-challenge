## Source audit

### Automation 023 — Assign Enrollment

- Source: `airtable/automations/shooting-challenge/023-submission-intake-and-asset-creation-assign-enrollment-to-submission.js`
- Script input: `recordId`
- Script behavior: resolves an Enrollment from existing valid link, Fillout ID,
  native Program Instance, linked Week's Program Instance, School Year, or the
  single-active-Enrollment fallback when no context exists.
- Script write: `Submissions.Enrollment` only.
- Repository recommendation: Athlete present; Enrollment empty or needs assignment.
- Required order: 023 must complete before 005's Activity Date fallback when
  Enrollment and Program Instance are needed.

### Automation 005 — Assign Week

- Source: `airtable/automations/shooting-challenge/005-submission-intake-and-asset-creation-assign-week-to-submission-homework-first.js`
- Script input: `recordId`
- Script behavior: Homework Name 1, then Homework Name 2, then
  Enrollment → Program Instance → active Week date-range fallback.
- Script write: `Submissions.Week` only.
- Repository recommendation: Week empty or `Needs Week Assignment? = 1`; Activity
  Date or Homework Name 1/2 present.
- August 2026 Early Bird exclusion: the current script does not hard-code or
  exclude August dates. It selects the unique active Week whose date range
  contains the Activity Date inside the Enrollment's Program Instance. This is
  correct only if the Early Bird Week is active and its dates are configured in
  Airtable.

### Downstream compatibility

- 031 requires both Enrollment and Week, then resolves one valid canonical
  Weekly Athlete Summary.
- 010 requires the counted Submission's Enrollment and Week and owns the
  Submission Base XP Event.
- The repository's offline chain regression proves 023 followed by 005 can
  assign Enrollment and Early Bird Week without manual Week linkage.
- No live trigger/view assertion is possible from repository sources alone.
