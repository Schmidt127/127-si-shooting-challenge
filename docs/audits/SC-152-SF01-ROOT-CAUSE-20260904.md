## Exact root cause

Automation **057** is triggered by `recordMatchesConditions` on a **single formula field**:

> `Perfect Week Calculation Queue? = 1` (`fldNvOVO3WidABUXS`)

That formula evaluates to **1** whenever Enrollment + Week + Goal Record are linked **and** `Perfect Week Automation Status` is **Pending or Ready**. It evaluates to **0** for blank / Skipped / Created / Error.

Airtable `recordMatchesConditions` fires when a record **newly matches** (typically a 0→1 / false→true edge), not on every subsequent update while the condition remains true.

Because Queue stays **1** for the entire Pending→Ready lifetime (and for any further helper/data updates while Status stays Ready), **057 does not re-enter** after the first successful queue entry. Eligible Weekly Athlete Summaries can therefore remain with stale helper fields and never re-evaluate until an operator forces Queue through a **0→1** edge (usually Status `Error`/`Skipped` → `Pending`).

Secondary stranding: Status left at **Skipped** / **Error** / **Created** / blank keeps Queue=0 forever even when Enrollment+Week+Goal are present — silent miss until a writable Status re-arm.

## Formula (authoritative)

```
IF(
  AND(
    Enrollment linked,
    Week linked,
    Goal Record linked,
    OR(Status = "Pending", Status = "Ready")
  ),
  1,
  0
)
```

Note: Queue depends on **Goal Record**, not Grade Band.

## Why this is a silent miss

- Observable: Queue?=1 with Ready and stale helpers; Automation Error often blank.
- No error run is recorded for the missed re-evaluation — 057 simply never starts.
- Operator reconciliation already listed in inventory: Queue?=1 stuck / Status Skipped without re-arm.

## What is NOT the root cause

- Not a missing 057 script version (live **2.3** matches GitHub).
- Not duplicate writers (057→058→059 is sequential).
- Not “formula Queue should be deleted” — keep formula; add a writable re-arm / reconciliation edge (Agent 2).
