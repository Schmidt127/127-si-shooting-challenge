## Exact root cause

Live UI trigger for **058** is **positive-only create** conditions:

1. `Perfect Week Eligible? = 1` (**formula**)
2. `Perfect Week Unlock` **is empty**
3. `Perfect Week Automation Status = Ready`

Script **v1.5** contains full lifecycle branches:

- Deactivate exact-owned unlock when enrollment inactive / not eligible / Status ≠ Ready / goal invalid
- Restore exact-owned unlock when eligibility returns
- Create only when no exact-owned unlock exists

Those withdrawal/restore branches **cannot execute in production** because the automation never starts when:

- Eligible flips **1→0** (trigger requires Eligible=1), or
- Unlock is already linked (trigger requires Unlock empty), or
- Status leaves Ready while Unlock remains linked

Net effect: once an unlock is linked, eligibility loss leaves an **Active** unlock (and often Awarded XP) with no automatic deactivation — a silent lifecycle miss.

## Why this is a silent miss

- Observable: Eligible?=0 (or helpers fail) while Perfect Week Unlock remains Active; Automation Error blank.
- Script already knows how to withdraw; UI conditions prevent the run.
- Historical SC-PW-E2E outcome `058_never_ran` is the create-path cousin of the same positive-only design.

## What is NOT the root cause

- Not missing deactivation code in v1.5 (code present; unreachable via live trigger).
- Not Milestone Source Key naming (v1.5 already correct).
- Not 059 (059 correctly awards Active+Pending unlocks; the miss is 058 failing to deactivate after eligibility loss).
